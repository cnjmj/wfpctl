v1.8  ·  2026-09

开始之前：所有增删改操作（add / del / update / sublayer-*）需要以管理员身份运行命令行（依赖系统 BFE 服务），否则会报"打开 BFE 引擎被拒绝"。查询类命令（list / show / layers / sublayers）无需管理员权限。

本手册以 wfpctl（C# 版）演示命令。三个版本命令与参数完全一致，仅程序名不同：wfpctl（C#）/ wfpctl_c（C）/ python wfpctl.py（Python）。

一、工具简介

wfpctl 是一个管理本机 Windows 过滤平台（WFP）过滤规则的命令行工具。WFP 是 Windows 内核级的网络过滤框架，系统防火墙即基于它实现。本工具通过官方 BFE 接口直接操作过滤规则，可实现按端口、IP 地址/网段、协议、应用程序的精细联网控制，规则重启系统后仍然生效。

工具的所有规则都挂在一个专属子层（wfpctl rules）下，与系统自带规则完全隔离——删除、修改操作绝不会影响 Windows 自身的防火墙规则。三个语言版本共用同一个子层，规则互相可见、互相可管理。

1.1 三个版本怎么选

版本运行条件特点适用场景
wfpctl.exe无（.NET Framework 4 为 Windows 自带）单文件 51KB，开箱即用，双击环境零依赖日常使用首选
wfpctl_c.exe无（纯原生程序）单文件零依赖，不依赖任何运行库；源码 C 标准自包含精简系统 / 无 .NET 环境
wfpctl.pyPython 3（标准库 ctypes）源码即文档，可阅读可改造，改完即生效无需编译二次开发 / 学习 WFP 原理

1.2 部署

  1. 获取程序

    将 wfpctl.exe（或 wfpctl_c.exe）复制到任意目录，例如 C:\Tools\wfpctl，即可直接使用，无需安装。

  2. 以管理员身份打开命令行

    开始菜单搜索 cmd 或 PowerShell，右键选择"以管理员身份运行"。

  3. 验证

    执行 wfpctl list，能看到规则列表（或"本工具创建 0 条"）即部署成功。

二、五个核心概念

理解以下五个概念即可顺畅使用本工具，每个都只用一句话。

1层（Layer）——规则挂在哪

决定规则在网络处理的哪个阶段生效。最常用的是"连接授权层"（connect/accept）：按每条连接判断一次，效率高且不会误伤已建立连接。

2子层（Sublayer）——规则的分组

本工具的规则默认放在专属子层"wfpctl rules"下，与系统规则隔离。也可以创建自定义子层做更细的分组管理。

3动作（Action）——匹配后做什么

block（阻断）或 permit（放行）。本工具默认 permit——即使忘了写动作，也只会"放行"而不会"断网"，安全第一。

4权重（Weight）——谁先说了算

同一子层内，权重高（0–15）的规则先评估，遇到第一条 block/permit 即定案。白名单场景的关键参数。

5持久化——规则活多久

默认持久（重启系统后仍生效）；--volatile 改为临时（BFE 重启即消失）；--boottime 创建为启动时间规则（系统开机、BFE 服务尚未启动时即生效，适合防护类规则）。

2.1 层别名速查

别名含义建议用途
connect-v4出站连接授权（IPv4）绝大多数场景用这四个：出站控制用 connect，入站控制用 accept。每个连接只判断一次，推荐。
connect-v6出站连接授权（IPv6）
accept-v4入站连接授权（IPv4）
accept-v6入站连接授权（IPv6）
out-v4 / out-v6出站传输层（每包）逐数据包过滤，粒度最细但开销大；需要切断已建立连接时才用。
in-v4 / in-v6入站传输层（每包）

完整层列表（本机 97 个）用 wfpctl layers 查看。add 的 --layer 参数也可以直接填层 GUID。

三、快速上手：三分钟加一条规则

以"封锁本机对外的 80 端口 TCP 出站连接"为例：

  1. 添加规则

    阻断必须显式写 --action block（默认是放行）。

  2. 查看结果

    wfpctl list 列出工具创建的规则，记下规则 ID。

  3. 验证与删除

    wfpctl show <ID> 看详情确认无误；不需要时 wfpctl del <ID> 删除。

:: 1. 添加（阻断出站 80 端口 TCP）
wfpctl add --name "禁出站80端口" --action block --protocol tcp --rport 80

:: 2. 查看工具创建的规则
wfpctl list

:: 3. 查看详情 / 删除
wfpctl show 68165
wfpctl del 68165

测试建议：拿不准效果时，先用 --volatile 参数添加临时规则（不持久化），确认无误后再正式添加；IP 类规则用 TEST-NET 保留地址（如 203.0.113.x）先演练。

四、命令详解

4.1 命令总览

命令功能管理员权限别名
add添加过滤规则需要—
del删除规则（按 ID 或按名称）需要delete

sublayer-del删除空子层需要—

4.2 add —— 添加规则

wfpctl add [--name 名称] [--desc 描述] [--action block|permit] [--layer 层]
           [--sublayer GUID] [--protocol 协议] [--lport 端口] [--rport 端口]
           [--lip 地址] [--rip 地址] [--app 程序路径]
           [--weight 0-15] [--boottime] [--volatile]
参数说明示例
--name规则显示名，默认 "wfpctl rule"--name "禁出站80"
--desc规则描述，可写用途备注--desc "运维工单#1024"
--action匹配后动作；默认 permit（放行），阻断必须显式 block--action block
--layer过滤层，别名或 GUID，默认 connect-v4--layer accept-v4
--sublayer所属子层 GUID，默认用内置子层（三版共享）--sublayer {GUID}
--protocoltcp / udp / icmp / icmpv6 / 数字 0-255 / any--protocol tcp
--lport本地端口：单值 80、范围 80-90、多值 80,443（多值拆成多条规则）--rport 80,443
--rport远程端口，写法同上--rport 80-90
--lip本地地址：单 IP / 前缀 / 掩码 / IPv6--lip 10.0.0.0/8
--rip远程地址，写法同上--rip 2001:db8::1
--app按应用程序过滤，文件必须存在（自动取应用 ID）--app C:\app\test.exe
--weight权重 0-15，同子层内高者优先评估；缺省由系统自动分配--weight 15
--boottime创建为启动时间规则（BFE 未启动时即生效）—
--volatile临时规则，不持久化（默认持久，重启仍生效）—

多端口展开：--rport 80,443 会创建两条规则，名称自动加 #1、#2 后缀（如"禁出站 #1"、"禁出站 #2"）。按名称删除时需带后缀，或用 del <ID> 逐条删。

4.3 list —— 列出与筛选规则

wfpctl list [--all] [--name 关键字] [--action block|permit] [--layer 层] [--sublayer GUID|default]
参数作用示例
（无参数）只显示本工具创建的规则（内置子层）wfpctl list
--all显示系统全部规则（约 700+ 条，含 Windows 自带）wfpctl list --all
--name按名称或描述关键字模糊筛选，不区分大小写wfpctl list --name 白名单
--action按动作筛选 block / permitwfpctl list --action block
--layer按层筛选wfpctl list --layer out-v4
--sublayer按子层筛选，支持 GUID / 名称关键字 / default 三种写法；名称模糊匹配、不区分大小写、可命中多个子层（如 --sublayer windivert）；自定义子层的规则只能用此参数查看wfpctl list --sublayer openvpn
 
:: 在系统全部规则里搜含"mssec"的（微软安全相关）
wfpctl list --all --name mssec

:: 组合筛选：默认子层 + permit 动作 + 名称含"白名单"
wfpctl list --action permit --name 白名单

4.4 update —— 修改规则

WFP 没有原地修改接口，update 采用事务内"删旧 + 建新"实现：要么整体成功，要么自动回滚，不存在中间状态。未指定的参数一律保持原值。

wfpctl update <规则ID> [--name ..] [--desc ..] [--action ..] [--protocol ..]
              [--lip ..] [--rip ..] [--lport ..] [--rport ..] [--app ..]
              [--weight 0-15|auto] [--layer ..] [--sublayer ..]
              [--boottime] [--volatile] [--persistent]
写法含义
update 123 --rport 443只改远程端口，其余全部保留
--rip any清除远程地址条件（any = 清除，适用于 lip/rip/lport/rport/app）
--weight auto恢复系统自动权重
--persistent把临时规则改回持久规则
端口参数限制update 每次只编辑一条规则，端口仅接受单值或单范围（80 或 80-90），不接受逗号多值

注意：由于"删旧建新"，修改后规则 ID 会变化（工具会打印"ID 旧 → 新"对照）。批量脚本中不要缓存旧 ID 反复 update——每次都要用新 ID。

4.5 del / show / 子层管理

:: 删除：按 ID 或按名称（名称为精确匹配）
wfpctl del 68165
wfpctl del --name "禁出站80端口"

:: 查看单条规则详情（条件、权重、标志一目了然）
wfpctl show 68165

:: 子层管理：创建 / 删除 / 列出
wfpctl sublayer-add {GUID} "分组名称" [权重0-65535]
wfpctl sublayer-del {GUID}
wfpctl sublayers
  • del --name 是精确匹配；多端口展开的规则要用带 #N 后缀的全名，或先用 list --name 找到 ID 再删。
  • 子层下还有规则时 sublayer-del 会拒绝删除，需先清空规则。
  • sublayer-add 幂等：子层已存在时直接返回成功。

五、典型场景

场景 1：封锁指定端口（最常用）

:: 禁止本机访问外部 80 端口（网页常见端口，谨慎使用）
wfpctl add --name "禁出站80" --action block --protocol tcp --rport 80

:: 一条命令禁多个端口：会拆成 2 条规则（#1、#2）
wfpctl add --name "禁常见端口" --action block --protocol tcp --rport 23,445

:: 禁止外部连入 3389（远程桌面）
wfpctl add --name "禁RDP" --action block --layer accept-v4 --protocol tcp --rport 3389

场景 2：禁止访问某个网站 / 网段

:: 按目标 IP 禁访问（单 IP）
wfpctl add --name "禁访问某服务器" --action block --rip 203.0.113.10

:: 按网段禁访问（24 位前缀 = 一个 C 段）
wfpctl add --name "禁访问某网段" --action block --rip 203.0.113.0/24

:: IPv6 同理
wfpctl add --name "禁IPv6目标" --action block --layer connect-v6 --rip 2001:db8::/32

域名限制说明：WFP 按 IP 匹配，域名需要先解析出 IP 再填。若目标站点使用 CDN（多 IP / 动态 IP），建议改用按应用或按端口的方式控制。

场景 3：禁止指定程序联网

:: 让某个程序完全无法出站（文件路径必须存在）
wfpctl add --name "禁某程序联网" --action block --app "C:\Program Files\test.exe"

:: 更精细：只禁该程序的 80 端口
wfpctl add --name "禁某程序网页访问" --action block --app "C:\Program Files\test.exe" --protocol tcp --rport 80

场景 4：白名单放行 + 整体阻断（权重组合）

权重决定同子层内的评估顺序：高权重先评估。经典组合：白名单例外用 15，整体封锁用 0——流量先匹配到高权重的 permit 例外即放行，否则落到低权重的 block 被拦。

:: 第 1 步：放行例外（权重 15，先评估）
wfpctl add --name "允许访问公司站" --rip 203.0.113.10 --weight 15

:: 第 2 步：整体封锁该网段（权重 0，后评估）
wfpctl add --name "封锁整个网段" --action block --rip 203.0.113.0/24 --weight 0

结果：访问 203.0.113.10 放行，访问该网段其余 IP 全部阻断。show 命令可查看每条规则的权重与系统计算出的"生效权重"。

场景 5：定位与修改现有规则

:: 1. 按关键字找到规则，拿到 ID
wfpctl list --name 白名单

:: 2. 就地修改：只改端口，其余不动
wfpctl update 68165 --rport 8443
已修改规则: ID 68165 → 68192  名称 = 站点白名单B

:: 3. 后续操作记得用新 ID
wfpctl show 68192

六、常见问题与故障排查

6.1 常见问题

Q: 报"打开 BFE 引擎被拒绝"？

A: 命令行不是管理员身份。右键 cmd/PowerShell 选"以管理员身份运行"。查询命令（list/show/layers）不受影响。

Q: 中文显示乱码？

A: C# 与 C 版已自动切换 UTF-8 输出。个别终端仍乱码时，先执行 chcp 65001 再运行工具；PowerShell 5.1 下可加 [Console]::OutputEncoding=[Text.Encoding]::UTF8。

Q: 规则重启电脑后还在吗？

A: 在。默认创建的就是持久规则。用 --volatile 添加的才是临时的（BFE 重启即消失）。list 的"标志"列：P=持久、B=启动时、I=已索引，"-"表示临时。

Q: 三个版本能混着用吗？

A: 完全可以。三版共用同一子层，exe 加的规则 py 能改，C 版删的规则 exe 也能看到。唯一注意点：update 后 ID 会变，跨版本操作时以 list 最新结果为准。

Q: 会误删 Windows 系统自带的防火墙规则吗？

A: 不会。工具的所有规则都挂在专属子层"wfpctl rules"下，默认 list / del / update 也只操作该子层。要操作系统规则必须显式带 --all（list 查看）或使用具体 ID——建议不要。

Q: del --name 找不到刚添加的多端口规则？

A: 多端口展开的规则名带 #N 后缀（如"禁常见端口 #1"），del --name 是精确匹配。改用 list --name 关键字 找到 ID 后按 ID 删除即可。

6.2 错误码速查

错误码含义处理办法
0x80070005拒绝访问以管理员身份运行命令行
0x80320003规则不存在ID 已变（update 过）或已删除，用 list 重新查
0x80320007子层不存在先 sublayer-add 创建子层

6.3 深入原理（选读）

深挖：为什么端口范围 1000-2000 会被拒绝？

WFP 的端口范围条件按网络字节序的数值区间匹配。端口 1000 存储为 0xE8 0x03，端口 2000 存储为 0xD0 0x07——转换后区间变成 0xE803 ~ 0xD007，起点大于终点，数值区间不成立，BFE 直接拒绝（0x80320020）。

规律：范围的两个端口若高字节相同（如 80-90、8000-9000），网络序后仍有序，可用；若高字节不同（如 1000-2000），大概率倒序被拒。工具遇到该情况会给出明确提示，此时改用逗号列举：--rport 1000,1001,...,2000 或拆成多个有序小段。

深挖：WFP 如何评估规则——层、子层与权重的顺序

网络数据到达某个过滤层时，WFP 的评估顺序是：层 → 子层（按子层权重从高到低）→ 子层内规则（按规则权重从高到低）。每个子层内的多条规则会聚合出一个结论，多个子层的结论再按"阻断优先"等仲裁逻辑合并出最终动作。

这就是白名单场景的原理：同子层内权重 15 的 permit 例外先被评估到并"定案"，权重 0 的整体 block 后评估——例外流量被放行，其余流量被拦。本工具默认子层权重为 0x0101，三版共享，因此它们的规则总在同一个评估组内按权重排序。

另外：boottime 规则之所以特殊，是因为它由 tcpip.sys 在开机时直接加载（此时 BFE 服务尚未启动），因此自身就隐含"持久"属性——这也是"BOOTTIME + PERSISTENT 组合会被拒绝"的原因。

深挖：从源码构建 C 版 / C# 版

C 版源码 wfpctl.c 完全自包含（WFP 结构体内嵌声明、运行时动态加载 fwpuclnt.dll），任何 C 编译器都能编译，无需 Windows SDK：

:: 本机无编译器时，用 PyPI 的 ziglang 工具链（自动下载 clang + MinGW 头）
pip install ziglang
python -m ziglang cc -target x86_64-windows-gnu -O2 -o wfpctl_c.exe wfpctl.c -lws2_32

:: 有 MSVC 时
cl /O2 wfpctl.c ws2_32.lib

:: C# 版（Windows 自带的 .NET Framework 编译器，无需安装）
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /out:wfpctl.exe wfpctl.cs

Python 版无需编译，直接 python wfpctl.py 运行（仅需 Python 3 标准库）。

安全使用三原则

一、阻断规则务必写 --action block，默认 permit 是安全垫底
二、先 list --name 定位，再 update / del，改后记得用新 ID
三、拿不准时加 --volatile 演练，确认后重建持久规则
